# Deploy with Neon and Render

Neon hosts PostgreSQL; Render runs the Express app. The app creates its tables on startup and requires a Neon connection string in `DATABASE_URL`.

## Prepare the database

1. Create a Neon project and database.
2. Copy the pooled connection string from Neon and keep it private. It should use SSL (`sslmode=require`).
3. Before deploying the app, import local data from this project directory while the local SQLite database is available:

   ```powershell
   $env:DATABASE_URL = "<Neon pooled connection string>"
   npm run db:import:sqlite
   ```

   The importer creates the PostgreSQL schema, refuses to import if any destination application table already contains rows, and runs the import in a transaction. It preserves users, requests, invoices, notifications, support messages, and activity logs. It deliberately skips active sessions, password-reset tokens, and old email-verification codes. Do not run it against a Neon database that already contains application data.

## Deploy the app

1. Push the current project files to GitHub.
2. In Render, create a Blueprint from the repository and select `render.yaml`.
3. Set `DATABASE_URL` to the Neon pooled connection string and provide `SUPER_ADMIN_EMAIL` and `SUPER_ADMIN_PASSWORD`. The password is used only if the imported database has no Super Admin.
4. Configure `SMTP_HOST`, `SMTP_USER`, `SMTP_PASS`, and `EMAIL_FROM` if email-based password recovery should send real messages. `SESSION_SECRET` is generated by the Blueprint.
5. Wait for the Render health check at `/healthz`, then open the service URL.

The Blueprint uses Render's free web-service plan. Its filesystem is ephemeral, so uploaded profile images are not durable across restarts or deploys. Use a paid persistent disk or external object storage before relying on uploaded files in production.

## Local run

Set `DATABASE_URL` and `SESSION_SECRET` in a local `.env` file, then run `npm install` and `npm start`. Never commit `.env` or put live credentials in `.env.example`.
